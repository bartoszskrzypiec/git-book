Dodatek B / Głębiej

Konfiguracja, którą warto mieć

Aliasy, rerere, pull.rebase, ustawienia diffa — z uzasadnieniem przy każdej pozycji, żeby dało się je świadomie odrzucić.

Zasada

Każde ustawienie ma mieć powód

Konfiguracje gita krążą po sieci jako gotowe pliki do skopiowania i to jest najgorszy sposób ich używania. Ustawienie, którego nie rozumiesz, zmienia zachowanie narzędzia w sposób, którego nie przewidzisz — a potem szukasz przyczyny w gicie.

Poniżej każda pozycja ma uzasadnienie i wskazanie, gdzie w książce opisany jest mechanizm, którego dotyczy. Wszystkie są opcjonalne: to lista do świadomego wyboru, nie plik do wklejenia.

Ustawiasz je przez git config --global <klucz> <wartosc>, a sprawdzasz przez git config --list --show-origin. Pamiętaj o trzech poziomach z Rozdziału 24: to, co ustawisz globalnie, może być nadpisane w konkretnym repozytorium.

Bezpieczeństwo

Cztery ustawienia, które chronią przed sobą samym

bezpieczniejsze domyślnezalecane
git config --global pull.rebase true
# pull nie tworzy commitow scalajacych przy nadrabianiu zaleglosci (R.10)

git config --global push.default simple
# push wysyla wylacznie biezaca galaz, i to pod ta sama nazwa (R.16)

git config --global push.autoSetupRemote true
# pierwszy push nowej galezi sam zapisuje upstream, bez -u (R.8)

git config --global alias.pushf "push --force-with-lease"
# gole --force zostaje o kilka znakow dalej niz wariant bezpieczny (R.17)

Ostatnia pozycja nie jest ustawieniem, tylko aliasem — ale należy do tej grupy, bo jej celem jest to samo: uczynić bezpieczny wariant tym łatwiejszym. Odruch sięga po to, co krótsze.

Warto rozważyć jeszcze jedno, o którym mało kto wie: git config --global rebase.autoStash true. Sprawia, że rebase z niezacommitowanymi zmianami sam je odkłada i przywraca, zamiast odmawiać. Wygodne, ale świadomie — bo oznacza, że rebase zaczyna dotykać katalogu roboczego.

Wygoda

Aliasy, które zarabiają na siebie

aliasyskróty do rzeczy robionych codziennie
git config --global alias.graf "log --oneline --graph --all --decorate"
# caly graf jednym slowem (R.12)

git config --global alias.moje "log --oneline origin/master..HEAD"
# co wnosze ponad galaz glowna — odpowiedz na wlasciwe pytanie (R.29)

git config --global alias.st "status -sb"
# krotki status z informacja ahead/behind

git config --global alias.ostatni "log -1 --pretty=%s"
# sama wiadomosc ostatniego commita — kontrola przed pushem (R.13)

Alias może wołać dowolną komendę gita, także z argumentami. Jeśli zaczyna się od wykrzyknika, git uruchamia go jako polecenie powłoki — to bywa przydatne, ale też jest najprostszym sposobem, żeby zrobić sobie krzywdę w cudzej konfiguracji.

Rozstrzyganie konfliktów

Dwa ustawienia, które oszczędzają powtarzanie

konfliktyzapamiętywanie i lepszy kontekst
git config --global rerere.enabled true
# zapamietuje rozwiazany konflikt i stosuje go ponownie (R.10, R.14)

git config --global merge.conflictStyle zdiff3
# markery pokazuja TAKZE wersje wspolnego przodka (R.11)

Drugie z tych ustawień zmienia to, co widzisz w pliku przy konflikcie: oprócz Twojej i cudzej wersji pojawia się także wersja bazowa. To zwykle rozstrzyga pytanie, która strona co zmieniła — bo bez bazy widać tylko dwa warianty, bez informacji, który z nich jest odejściem od stanu wyjściowego.

Pierwsze przydaje się szczególnie przy rebasie długiej gałęzi, gdzie ten sam konflikt potrafi wrócić przy kilku commitach z rzędu. Warto wiedzieć, że rerere zapamiętuje rozwiązania lokalnie i nie dzieli się nimi z nikim.

Tożsamość i higiena

Reszta

podstawywarto ustawić raz na maszynie
git config --global user.name "Imie Nazwisko"
git config --global user.email "adres@firma"
# w konkretnym repo mozna nadpisac bez --global (R.24)

git config --global core.autocrlf input
# albo true na Windowsie — zalezy od konwencji projektu

git config --global core.excludesFile ~/.gitignore_global
# smieci edytora i systemu, poza repozytorium projektu (R.7)

git config --global fetch.prune true
# kazdy fetch sprzata nieistniejace juz galezie zdalne (R.8)

Ustawienie core.autocrlf zasługuje na ostrzeżenie: dotyczy zamiany znaków końca linii i potrafi wygenerować diff obejmujący cały plik, jeśli jest ustawione niespójnie w zespole. Jeżeli projekt ma plik .gitattributes, to on decyduje i lepiej mu nie przeszkadzać.

Na koniec jedno ustawienie, którego nie warto włączać bez potrzeby: automatyczne podpisywanie commitów. Jest sensowne tam, gdzie projekt tego wymaga, ale bez działającej konfiguracji kluczy zamienia każdy commit w potencjalny błąd — a nie daje nic, dopóki nikt tych podpisów nie sprawdza.
